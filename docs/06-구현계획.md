# 구현 계획: M3 이후 (제안)

M1·M2는 구현을 마쳤다. 이 문서는 그 뒤의 제작 순서 제안이다. 규칙은 [기획서](02-기획서.md), 용어는 [CONTEXT.md](../CONTEXT.md), 이전 마일스톤은 [마일스톤](archive/03-마일스톤.md)에 있다. 전체가 제안 단계다.

## 방침

**얇은 수직 슬라이스를 먼저 만들고 두껍게 한다. 규칙 코어만 처음부터 단단하게 만든다.**

- ADR-0005가 미확정이라, 복도·방 연출을 먼저 완성하면 #8 판정에서 버려질 수 있다.
- 아트가 미정이라 화면 완성도 작업은 아트가 들어오면 다시 해야 한다.
- 수치가 미확정이라 30일을 실제로 돌려 봐야 목표(5단계 20일 전후, 공격 2~3일에 한 번)를 검증할 수 있다.
- 2인 팀이 겹치지 않게 나누려면 뼈대가 먼저 있어야 한다.
- 예외: 호감도·타락도·차이·NTR 규칙은 얽혀 있고 NTR은 복구 불가([ADR-0001](adr/0001-NTR-복구불가-옵션없음.md))라 처음부터 EditMode 테스트로 정확하게 만든다. 표현은 얇게, 규칙은 두껍게.

## 시작 전에 끝낼 것

스펙(`/to-spec`)과 티켓(`/to-tickets`)은 아래 셋 뒤에 한다.

1. **#8 판정** (사람 몫). 규칙 코어는 ADR-0005와 무관하다. 판정에 영향받는 건 M6뿐이다.
2. **도메인 모델 세션** (`/grill-with-docs`). 정할 것:
   - 하루 끝 처리 순서: 방치 상승, 약속 연체, 음란도 감소, 3:1 연동, 새벽 공격, NTR 확정
   - "다음날 확정"의 정확한 시점
   - 3:1 연동의 나머지 처리 (누적 카운터 또는 내림)
   - "최근 3일" 기록 저장과 표적 동률 처리
3. **세이브 구조 ADR**: 슬롯 세이브와 영구 갤러리 해금의 분리 여부, 저장 시점.

## 구조 제안

- `NovaLux.Domain` 어셈블리(`noEngineReferences`)와 `NovaLux.Tests.EditMode` 어셈블리를 새로 둔다.
- 도메인은 상태, 명령, 결과 이벤트로 구성한다. 수치는 `Balance`로 주입하고, 랜덤은 주입하거나 결정론적으로 바꾼다 (ADR-0004의 결정론 원칙).
- `NovaLux.Runtime`은 Domain을 참조한다. 화면은 명령을 보내고 이벤트를 그린다.
- 상태는 `JsonUtility`가 다루는 배열과 평범한 클래스로만 설계한다 (Dictionary·다형성 불가). 도메인에 `MonoBehaviour`와 static 싱글턴을 섞지 않는다.
- 열린 에디터에서 PlayMode 테스트가 0/0이 되는 문제가 있어 EditMode를 주력으로 쓴다. EditMode에서도 같은 증상이 나는지는 확인하지 않았다.

## 테스트 이음새 확장

- 이음새 A (EditMode, 순수 도메인): 규칙 단위, 30일 시나리오, 불변식 속성, 세이브 왕복. 주력.
- 이음새 B (기존 PlayMode 입력 구동): 입력이 명령으로 이어져 화면에 반영되는지. 대표 흐름만.
- 세이브 경로·시간·랜덤은 주입 가능하게 한다 (`Settings.FilePath` 패턴).
- 특정 상태(예: 15일차)로 바로 시작하는 디버그 상태 주입을 테스트와 공유한다.

## ADR 후보

1. 도메인을 UnityEngine과 분리한 순수 C# 어셈블리, 명령·이벤트 경계
2. 하루 끝 처리 순서와 "다음날 확정" 시점
3. 세이브 구조: 슬롯과 영구 해금 분리, 포맷, 버전, 저장 시점
4. 수치 데이터의 위치 (코드 기본값, ScriptableObject, JSON)와 밸런싱 방식
5. 랜덤성 정책 (결정론 또는 시드 RNG)
6. 화면 흐름과 씬 구조 (씬 추가 또는 단일 씬 스택)
7. 대사·이벤트 데이터 포맷 ([ADR-0006](adr/0006-자체-문자열-표와-언어별-서체.md)의 후속)
8. ADR-0005 확정 여부 (#8)

## 첫 티켓 후보

1. `NovaLux.Domain`·EditMode 어셈블리 신설과 관계 수치 코어: 호감도·타락도·음란도 범위 0~100, 3:1 연동, 음란도 배율, 차이, 5.1 자격 표. EditMode가 배치로 실행되는지와 0/0 증상 확인 포함. 도메인 세션 없이 시작 가능.
2. 하루·칸 진행 코어: `GameState`, 칸 소모, `EndDay`, 대화·방치 상승, 연인 전환, 약속 연체, NTR 확정, 30일 엔딩 판정, 30일 시나리오 테스트. 처리 순서가 정해진 뒤.
3. 세이브 슬롯 왕복과 이어하기 활성화. 세이브 ADR 뒤.

#8은 이미 `ready-for-human`으로 열려 있다. M6 티켓의 블로커로 연결한다.

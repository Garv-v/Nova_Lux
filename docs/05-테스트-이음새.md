# 테스트 이음새: 입력으로 화면 상태 관찰

용어는 [CONTEXT.md](../CONTEXT.md), 배경은 [스펙 M1+M2](04-스펙-M1M2.md)의 Testing Decisions.

## 입력 구동 방법 (확인함)

- **Unity CLI에는 키·포인터 시뮬레이션 도구가 없다.** `unity list`(151개)에 입력 주입 명령이 없고, 테스트 실행용 `run_tests`·`list_tests`·`test_status`만 있다.
- **Input System의 `InputTestFixture`(Play Mode 테스트)를 쓴다.** `com.unity.inputsystem` 1.20.0의 `Unity.InputSystem.TestFramework` 어셈블리다. 가상 `Mouse`/`Keyboard`를 추가하고 `Set(...)`, `Click(...)`, `Press(...)`로 입력을 넣는다.
- 마우스 클릭은 버튼의 화면 좌표를 구해 넣는다: `RectTransformUtility.WorldToScreenPoint(null, rt.TransformPoint(rt.rect.center))`(Screen Space Overlay 기준). 위치를 `Set(mouse.position, …)`한 뒤 한 프레임 쉬고 `Click(mouse.leftButton)`한다.
- 관찰은 화면에 드러난 상태로 한다: `Object.FindObjectsByType<Button>()`의 개수·`interactable`, `SceneManager.GetActiveScene().name`.

## 실행

```bash
unity command run_tests --mode PlayMode --async_tests true
unity command test_status      # completed: N/N 통과
```

`--async_tests`를 주지 않으면 `0/0 통과`로 바로 돌아온다(실행 안 됨).

## 이음새 설계

- 종료는 `AppQuit.Handler`로 가로챈다. 테스트가 호출 횟수를 센다. null이면 실제로 끈다(에디터에서는 Play 종료).
- 해상도·전체화면 적용은 `ScreenSettings.Handler`로 가로챈다(`UiTestFixture`가 `ScreenCalls`에 모은다). null이면 `Screen.SetResolution`을 부른다. 에디터 Game View는 이 호출을 무시한다.
- 레터박스는 `Letterbox.Fit`(순수 함수)과 `Letterbox.Layout(w, h)`로 검증한다. 검은 띠 캔버스는 sortingOrder 1000이라, 다른 Overlay 캔버스는 이보다 낮게 둔다.
- 씬 이름은 `SceneNames` 상수를 쓴다. 씬은 `Assets/Scenes/`에 있고 빌드 목록에 등록돼 있어야 `SceneManager.LoadScene`이 된다(Title=0, Hallway=1).
- 새 PlayMode 테스트는 `InputTestFixture`를 상속하고 `Setup`/`TearDown`을 override해 `base`를 먼저/나중에 부른다.

## CLI 사용 메모

- `unity command <이름> --<파라미터> <값>` 형식이다. JSON을 통째로 넘기면 첫 파라미터에 문자열로 들어간다.
- `capture_game_view --source screen`은 Play Mode에서만 된다. `save_path`는 프로젝트 안 상대 경로이고 `Assets/` 밑에 저장된다(`Temp/x.png` → `Assets/Temp/x.png`). 보고 나면 `delete_asset`으로 지운다.

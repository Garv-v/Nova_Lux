# 스펙: 초기화면·환경설정과 복도 프로토타입 (M1+M2, 미확정)

> **보관 문서.** M1·M2는 구현을 마쳤고 ADR-0005는 2026-10-29에 `accepted`로 확정됐다. 아래는 당시 기록이라 "미확정"·"판정 후" 표현은 현재와 다르다. 현재 동작은 코드와 테스트, 규칙은 [기획서](../02-기획서.md)를 본다.

용어는 [CONTEXT.md](../../CONTEXT.md), 규칙은 [기획서](../02-기획서.md), 순서는 [마일스톤](03-마일스톤.md), 결정 이유는 [ADR](../adr/)에 있다. 빌라 안 표현 방식([ADR-0005](../adr/0005-복도횡스크롤-방아이소.md))이 제안 단계라, 이 스펙의 M2는 프로토타입으로 검증하는 것이 목적이다.

## Problem Statement

팀(2명)이 게임을 만들기 시작할 첫 화면과 설정이 없다. 빌라 안을 "복도는 횡스크롤, 방은 아이소메트릭 한 장"으로 보여 주겠다는 결정도 제안일 뿐, 실제로 걸어 보고 제작 부담이 되는지 확인한 적이 없다. 그 결정이 틀리면 방과 포즈 장면 제작이 전부 흔들린다.

## Solution

플레이어는 초기화면에서 환경설정(음량, 텍스트 속도, 해상도, 언어 등)을 바꾸고 저장하며, 갤러리가 잠긴 자리로 있는 것을 본다. 새로 시작하면 빌라 복도에서 금태양을 좌우로 걷게 하고, 문 앞에서 입장해 방 임시 화면으로 넘어갔다가 복도로 돌아올 수 있다. 개발자는 이 프로토타입으로 복도 걷기가 조작과 제작 면에서 감당할 만한지 판정한다.

## User Stories

1. 플레이어로서, 초기화면에서 새로 시작 / 이어하기 / 갤러리 / 환경설정 / 종료를 보고 싶다. 무엇을 할 수 있는지 한눈에 알기 위해서다.
2. 플레이어로서, 새로 시작을 눌러 복도로 들어가고 싶다. 게임을 시작하기 위해서다.
3. 플레이어로서, 종료를 눌러 게임을 끄고 싶다. 쉽게 나가기 위해서다.
4. 플레이어로서, 환경설정을 열고 닫고 싶다. 초기화면으로 되돌아가기 위해서다.
5. 플레이어로서, BGM 음량을 조절하고 싶다. 배경음만 줄이기 위해서다.
6. 플레이어로서, 효과음 음량을 조절하고 싶다. 효과음만 줄이기 위해서다.
7. 플레이어로서, 보이스 음량을 조절하고 싶다. 목소리만 따로 맞추기 위해서다.
8. 플레이어로서, 텍스트 속도를 바꾸고 싶다. 읽는 속도에 맞추기 위해서다.
9. 플레이어로서, 자동 진행 속도를 바꾸고 싶다. 대사가 넘어가는 간격을 맞추기 위해서다.
10. 플레이어로서, 전체화면과 창모드를 전환하고 싶다. 환경에 맞게 쓰기 위해서다.
11. 플레이어로서, 해상도를 720p, 1080p, 2K, 4K 중에서 고르고 싶다. PC 사양과 모니터에 맞추기 위해서다.
12. 플레이어로서, 16:9가 아닌 모니터에서도 화면이 일그러지지 않고 레터박스로 보이길 원한다. 화면이 찌그러지지 않기 위해서다.
13. 플레이어로서, 언어를 한국어와 일본어 중에서 바꾸고 싶다. 읽기 편한 언어로 즐기기 위해서다.
14. 플레이어로서, 언어를 바꾸면 모든 화면의 문자열이 즉시 바뀌길 원한다. 한 화면에만 남은 옛 언어가 없도록 하기 위해서다.
15. 플레이어로서, 설정을 바꾸고 게임을 껐다 켜도 값이 유지되길 원한다. 매번 다시 맞추지 않기 위해서다.
16. 플레이어로서, 갤러리 버튼을 누르면 해금 전 컷신이 잠긴 이미지로 보이길 원한다. 앞으로 모을 것이 있음을 알기 위해서다.
17. 플레이어로서, 갤러리가 비어 있어도 에러 없이 돌아오고 싶다. 안정적으로 쓰기 위해서다.
18. 플레이어로서, 복도에서 좌우 키로 금태양을 걷게 하고 싶다. 빌라를 돌아다니기 위해서다.
19. 플레이어로서, 복도 끝에서 금태양이 더 나가지 않고 멈추길 원한다. 화면 밖으로 사라지지 않게 하기 위해서다.
20. 플레이어로서, 카메라가 금태양을 따라가되 복도 경계를 넘지 않길 원한다. 빈 공간이 보이지 않게 하기 위해서다.
21. 플레이어로서, 문 앞에 서면 입장할 수 있다는 표시를 보고 싶다. 어느 문이 열리는지 알기 위해서다.
22. 플레이어로서, 입장하면 페이드로 방 화면으로 넘어가고 싶다. 화풍이 다른 두 화면이 어색하지 않게 하기 위해서다.
23. 플레이어로서, 방에서 나가면 같은 문 앞의 복도로 돌아오고 싶다. 어디서 나왔는지 알기 위해서다.
24. 플레이어로서, 복도에서 문을 오가는 이동이 행동력을 쓰지 않길 원한다. 걷는 것이 부담이 되지 않게 하기 위해서다.
25. 플레이어로서, 방 안에서 상호작용 자리가 표시되길 원한다. 나중에 행동력을 쓰는 곳을 알기 위해서다.
26. 개발자로서, 복도 프로토타입을 만들어 걷기의 조작감과 제작 부담을 판정하고 싶다. ADR-0005를 확정할지 바꿀지 결정하기 위해서다.
27. 개발자로서, 모든 화면이 720p, 1080p, 4K에서 깨지지 않는지 확인하고 싶다. 해상도 지원 범위를 믿고 가기 위해서다.
28. 개발자로서, 한글과 일본어 문자가 깨지지 않고 나오는지 확인하고 싶다. 두 언어 지원이 현실적인지 알기 위해서다.
29. 개발자로서, 아트 없이 임시 박스로도 모든 화면이 동작하길 원한다. 아트가 늦어져도 개발이 막히지 않기 위해서다.

## Implementation Decisions

전체가 제안 단계다.

- **화면 기준**: 1920×1080 기준으로 만들고, 실행 때 선택한 해상도로 스케일링한다. 비율은 16:9 고정이고 남는 곳은 레터박스로 채운다. 해상도 옵션은 720p~4K다.
- **설정 모듈**: 음량 3종, 텍스트 속도, 자동 진행 속도, 전체화면/창모드, 해상도, 언어의 값을 보관한다. 변경하면 즉시 저장하고 실행 때 불러와 적용한다. 저장 방식은 구현 때 정한다.
- **문자열 모듈**: 한국어와 일본어 표를 두고 언어를 바꾸면 모든 문자열을 교체한다. 방식(Unity Localization 패키지 또는 자체 표)은 구현 때 정한다. 확인 안 함.
- **폰트**: 한글과 일본어를 함께 쓰므로 글리프 범위와 폰트 아틀라스 크기를 시작 전에 확인한다.
- **초기화면**: 새로 시작은 복도로 이동한다. 종료는 게임을 끈다. 이어하기는 세이브 구조가 없으므로 이번 범위에서는 자리만 둔다. 비활성(흐린 색)으로 표시하고 키보드 이동에서 건너뛴다. 세이브가 생기면 저장 파일이 있을 때만 활성화한다.
- **갤러리**: 버튼은 활성이다. 열면 컷신 자리가 모두 잠긴 이미지로 보인다. 실제 해금 연결은 이번 범위가 아니다.
- **복도**: 금태양 한 명만 좌우로 걷는다. 스프라이트는 크기 단계와 무관한 한 세트이고, 이번에는 임시 도형이다. 카메라는 금태양을 따르며 복도 경계를 넘지 않는다.
- **문**: 문 앞에 서면 입장 표시가 뜨고, 위(W, ↑)를 누르면 페이드로 방 임시 화면으로 넘어간다. 방에서도 위(W, ↑)를 누르면 나가고(마우스는 나가기 버튼), 같은 문 앞으로 돌아온다. 걷기는 A/D, ←/→다. 패드는 지원하지 않는다.
- **ESC 메뉴**: 복도와 방에서 Esc로 연다(다시 누르면 닫힘). 계속하기 / 저장 / 불러오기 / 환경설정 / 타이틀로가 있고, 저장·불러오기는 세이브 구조가 생기기 전까지 비활성이다. 열려 있는 동안 걷기·문 입장·방 나가기는 멈춘다. 환경설정은 메뉴 위에 열린다.
- **이동 비용**: 복도 걷기와 방 입장은 행동력을 쓰지 않는다. 방 안의 상호작용 자리는 표시만 하고 동작은 이번 범위가 아니다.
- **판정 지점**: M2가 끝나면 걷기가 감당할 만한지 본다. 괜찮으면 ADR-0005를 `accepted`로 바꾸고, 아니면 아이소 화면 탭 이동으로 바꾼다.

## Testing Decisions

- 좋은 테스트는 내부 구현이 아니라 외부에서 보이는 동작만 확인한다.
- **이음새는 하나**: Play Mode에서 입력을 넣어 실제 게임을 돌리고, 화면에 드러난 상태를 관찰한다.
  - 초기화면에서 환경설정을 열어 값을 바꾼다. 씬을 다시 불러 값이 유지되는지 본다.
  - 언어를 바꾸면 화면의 문자열이 바뀌는지 본다.
  - 복도에서 걷다 문으로 들어가고, 방에서 나와 복도로 돌아오는 왕복을 본다.
- 입력은 Unity CLI의 키·포인터 시뮬레이션 같은 입력 구동 도구로 넣을 수 있다. 어떤 도구를 쓸지는 구현 때 확인한다.
- **테스트로 못 잡는 것**: 해상도별 UI 깨짐, 복도 비율, 한글·일본어 글리프는 720p, 1080p, 4K 스크린샷으로 눈으로 확인한다.
- 참고할 기존 테스트는 없다. 프로젝트에 코드와 테스트가 아직 없다.

## Out of Scope

- 아이소메트릭 방의 포즈 장면과 공실 엿보기
- 하루 4칸 진행과 행동력 루프, 새벽 공격과 방어
- 컷신과 갤러리의 실제 해금, 세이브 슬롯과 이어하기 동작
- 크기 단계별 금태양 표현
- 최종 아트
- 빌라 밖 지도 화면

## Further Notes

- 이 스펙은 전체가 미확정이다. 특히 복도 횡스크롤은 M2 판정으로 확정 여부가 갈린다.
- 이어하기와 갤러리 해금은 세이브 구조가 정해진 뒤에 다룬다. 갤러리 해금 정보를 세이브 슬롯과 별개로 영구 저장할지도 그때 정한다.
- 이슈 트래커 설정이 없어 아직 발행하지 않았다. 트래커가 정해지면 이 내용을 이슈로 올린다.

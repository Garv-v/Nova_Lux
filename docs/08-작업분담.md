2인 팀: **Adella**(아트 + 아트 이음새 코드), **장대희**(도메인·하루 루프 코드, 코드 비중이 더 큼). 각자 자기 AI 에이전트로 일한다. **장대희의 AI는 이 문서 하나만 읽고 일을 시작할 수 있어야 한다.**

- 근거 문서는 `origin/main` 기준이다. **두 사람 모두 첫 작업은 `main`을 pull 하는 것이다.**
- 이 계획은 Opus가 작성하고 다른 Opus가 저장소와 대조해 검증한 뒤 고친 것이다. 검증에서 확인하지 못한 것은 "확인 못 함"으로 남겼다.
- 범위는 `docs/06-구현계획.md`의 **M3(도메인 코어와 30일 루프 뼈대, 박스 UI, 엔딩은 텍스트)** 와, 아트가 코드를 기다리지 않게 하는 **아트 이음새**다. M4 이후는 "이후"로만 적는다.

## 0. 시작 전 정리

1. main을 pull 한다. 기술스택 문서는 `docs/07-유니티-최신-기술스택.md`로 main에 있다(번호가 `06-구현계획.md`와 겹치지 않게 07로 했다).
2. 작업과 무관한 미커밋 변경(폰트 SDF 에셋, `UniversalRP*.asset`, `LiberationSans SDF.asset`, iet-framework 설정)은 작업 브랜치에 섞어 커밋하지 않는다. 에디터가 재직렬화한 것으로 보이며 의도한 변경인지는 확인하지 못했다.
3. 브랜치 이름: README 규칙은 `이름/작업내용`(영문 소문자, 하이픈)이다. 실제로는 `feat/…`, `chore/…`, `docs/…`를 써 왔다. 이 문서는 **`<이름>/<이슈번호>-작업내용`**(예: `adella/31-art-slots`, `fiercewolf701/32-domain-core`)을 쓴다. 장대희의 GitHub 계정은 `fiercewolf701`이다(협업자 목록·README 예시로 확인하고 Adella가 본인이라고 확인했다). 브랜치 접두어는 이 계정 이름을 쓴다.
4. 이슈 번호는 만들 때 정해진다(2026-10-29 기준 #31부터. 이슈와 PR이 번호를 함께 쓴다). 위 예시의 번호는 자리 표시다.
5. **ADR-0005는 `accepted`(2026-10-29)다.** 복도·걷기·문 아트와 코드는 최종까지 진행한다. 720p·1080p·4K 복도 비율은 에디터 정지 화면(카메라 렌더)에서 확인했고 같았다. Play Mode 카메라 추적과 16:9가 아닌 모니터의 레터박스는 확인하지 않았다.

## 2. 계약 (아트 ↔ 코드)

원칙: **코드는 슬롯이 비어 있으면 지금의 임시 도형으로 돈다. 아트는 슬롯에 넣으면 끝이다.** `UiTheme`에 이미 있는 패턴(`null`이면 단색, `UiKit.NewIconChip`의 `iconImage.enabled = icon != null`)을 월드 아트로 넓힌다.

### 2.1 월드 좌표와 PPU (현재 씬에서 확인한 값)

- `Hallway.unity` 카메라 `orthographic size: 5` → 화면 세로 10유닛, 16:9에서 가로 17.78유닛. 1920×1080 기준 **1유닛 = 108px**.
- 복도 배경은 `Assets/Art/Temp/Square.png`(4×4px, PPU 4 = 1유닛)를 `scale (54, 10)`으로 늘린 것이다. 복도는 **54 × 10 유닛**. `Hallway.XMin/XMax`는 SpriteRenderer bounds에서 읽는다.
- 바닥 윗면 y = -3(Floor y -5~-3). `GoldSun` 원점 y = -3.
- 문: `Door_mine` x = -15, `Door_neighbor` x = +9. 지금은 Square를 scale (2, 4)로 키운 것이고 **중심 y = -2**다(바닥에 1유닛 묻혀 있다).

**월드 크기(유닛)가 약속이고 PPU는 그에 맞추는 값이다.** 1배 제작(1080 기준)은 PPU 108, 2배 제작(4K 대비)은 PPU 216. 제작 해상도는 기획서 10장이 미확정이라 정하지 않는다.

| 대상 | 월드 크기 | 1배 픽셀 | 피벗 | 놓이는 자리 |
|---|---|---|---|---|
| 복도 배경 | 54 × 10 유닛 | 5832 × 1080 | 가운데 | (0, 0). 바닥선은 아래에서 216px(= y -3) |
| 문(각각) | 2 × 4 유닛 | 216 × 432 | **아래 가운데** | (문 x, **-3**) |
| 금태양 프레임 | 캔버스 3 × 4 유닛, 인물 키 약 2.9유닛 | 324 × 432 (인물 키 약 313) | **아래 가운데 = 발끝** | (x, -3) |
| 타이틀 배경 | 화면 전체(UI) | 1920 × 1080 | — | 초기화면 버튼 뒤 |

- 금태양은 **오른쪽을 보게** 그린다. 왼쪽은 코드가 `flipX`한다. (기획서 10장은 "좌우 한 세트만 만든다"를 아직 미확정으로 표기한다. 반전으로 한 세트만 쓰는 것은 **가정**이다.)
- 문의 "입장" 표시는 코드가 `sprite.bounds.max.y + 0.8`에 띄운다(`Door.cs`). 아트는 신경 쓰지 않는다.
- **문 위치 변경**: 계약대로 문 아래를 y = -3에 두면 문이 지금보다 1유닛 올라간다. 이것은 "카메라·이동 수치 변경 금지"의 예외로 C0a에서 의도적으로 한다.

### 2.2 텍스처 임포트 설정

폴더별 `AssetPostprocessor`(C0a)가 **자동으로 적용**한다. Adella는 Inspector에서 손으로 맞추지 않는다. 적용 값은 아래 표다.

| 항목 | 월드 스프라이트(복도·문·금태양·타이틀 배경) | UI 아이콘·알약·원 |
|---|---|---|
| Texture Type | Sprite (2D and UI) | 같음 |
| Pixels Per Unit | 108(1배) 또는 216(2배). 한 묶음 안에서 통일 | 100(지금 생성기와 동일) |
| Pivot | 2.1 표 | Center |
| Max Size | 원본 이상. **Unity 6000.6의 상한을 구현 때 확인한다(8192인지 16384인지 확인 못 함).** 기본값 2048이면 5832px 배경이 줄어든다 | 기본값 |
| Mip Maps | 1배 제작이면 끔, 2배 제작이면 켬(가정. 해상도 결정 때 다시 본다) | 켬 |
| Filter | Bilinear(가정. 픽셀아트로 가면 Point) | Trilinear |
| Compression | None 또는 High Quality | None |
| 9-slice | — | `pill`만 Border L96 B95 R96 T95 |

UI 아이콘은 **흰색 그림 + 투명 배경**이다. 코드가 `theme.iconColor`·`chipColor` 등으로 색을 입힌다. 색은 이미지가 아니라 `UiTheme.asset`의 색 값으로 바꾼다.

파일명은 영문 소문자와 밑줄, 번호는 두 자리다. 코드는 파일명이 아니라 에셋의 **슬롯 참조**로 스프라이트를 읽는다. 이름은 관례이고 슬롯에 넣는 것이 계약이다. PNG는 Git LFS로 관리된다(`.gitattributes`). 원본 `.psd`는 저장소에 올리지 않는다(README).

### 2.4 슬롯 이름

**`UiTheme`(이미 있음)**: 스프라이트 13개 = `pillSprite`(384×192), `circleSprite`(192×192), 아이콘 10개(`iconNewGame`, `iconContinue`, `iconGallery`, `iconSettings`, `iconQuit`, `iconBgm`, `iconSfx`, `iconVoice`, `iconTextSpeed`, `iconAuto`), `iconLocked`. 아이콘은 128×128. 색 슬롯은 `buttonColor`, `accentColor`, `textColor`, `panelColor`, `chipColor`, `iconColor`, `scrimColor`, `lockedSlotColor` 등.
**C0a가 추가**: `titleBackground`(Sprite, null이면 배경 없음. 지금 화면 그대로).

**`GameArt`(C0a가 새로 만든다. `Assets/Resources/GameArt.asset`)**
- `hallwayBackground`(Sprite)
- `doors`(배열 `{ string doorId; Sprite closed; Sprite highlight; }`, doorId는 씬의 `Door.id`와 같다. 지금 `mine`, `neighbor`)
- `goldSunIdle`(Sprite[]), `goldSunWalk`(Sprite[]), `goldSunWalkFps`(float, 기본 10, 가정)
- `slotIcons`(Sprite[4], 순서는 아침·점심·저녁·새벽)
- `heroinePortraits`(배열 `{ string heroineId; Sprite portrait; }`, 선택)

**애니메이션 상태**는 `idle`, `walk` 두 개다. Animator Controller는 쓰지 않는다(코드가 프레임 배열을 재생하는 플립북). 상태를 더하면 계약 변경이다.

### 2.5 `UiTheme.asset` 규칙 (함정 있음)

새 필드를 C#에만 더하는 방식은 이미 쓰고 있고 잘 돈다(에셋에 없는 필드는 C# 초기값으로 읽힌다. 예: `pauseButtonSize`). 함정:

1. **에셋에 이미 직렬화된 필드는 C# 기본값을 바꿔도 반영되지 않는다.** 예: 에셋은 `rowGap: 84`, `firstRowY: 340`인데 C#은 95, 330이다. Adella가 에셋을 저장하면 그 시점의 새 필드가 에셋에 박힌다. 이미 있는 필드의 값을 바꾸려면 **C# 기본값이 아니라 Adella에게 에셋 값 변경을 요청**한다.
2. Adella가 슬롯 하나만 바꿔도 에디터가 에셋 전체를 다시 쓴다. 첫 PR에 누락 필드가 일괄 추가되는 것은 정상이다.
3. **Adella의 색·스프라이트 변경이 기존 PlayMode 테스트를 깰 수 있다.** `SettingsStyleTests.DefaultTheme_TextContrast_MeetsWcagAa`(색 대비), `TitleStyleTests.DefaultTheme_HasUiSprites`(pill border > 0). UiTheme을 바꾼 PR은 **배치 PlayMode 테스트를 돌린 뒤** 올린다.

### 2.6 Sorting Layer와 캔버스 순서

- **Sorting Layer는 이번 범위에서 바꾸지 않는다.** 지금 `Default` 하나와 `sortingOrder`(배경 -10, 기둥·바닥 -9, 문 -8, 금태양 Body 0 / Head 1, 입장 표시 10)로 순서가 맞는다. `Foreground` 등이 필요해지면 그때 `TagManager.asset`을 단독 PR로 바꾼다.
- Screen Space Overlay 캔버스 `sortingOrder`(코드로 확인한 값): 0 초기화면, 100 방 화면, **150 HUD(새, 가정)**, 200 ESC 메뉴, 900 페이드, **910 날짜 전환 글자(새, 가정)**, 1000 레터박스. 다른 캔버스는 1000보다 낮게 둔다.

### 2.7 문자열 키 (장대희만 `Loc.cs`를 고친다)

- 형식은 `<화면>.<항목>`, 항목은 camelCase다(기존 `title.newGame`, `room.exit`). 문 id와 방 제목은 `room.<문id>`로 이어진다.
- 새 접두어: `hud.*`, `weekday.mon`~`weekday.sun`, `action.*`, `heroine.<id>.name`(이름 미확정이라 "여주 1" 같은 자리 값), `ending.*`, `debug.*`.
- 한국어를 더하면 일본어도 함께 쓴다(`LanguageTests`가 잡는다, ADR-0006). 접두어마다 빈 줄로 구분한 블록을 새로 만들고(첫 줄에 `// hud` 같은 주석) 그 안에 더해 병합 충돌을 줄인다.

### 2.8 기다리지 않게 하는 장치

1. 코드는 임시 아트로 먼저 돈다. 슬롯이 `null`이면 지금의 도형. 테스트는 `GameArt`가 비어 있어도 통과해야 한다.
2. 아트는 계약만 지키면 코드 없이 바뀐다. PNG를 폴더에 넣으면 임포트가 자동으로 맞춰지고, 슬롯에 끌어 놓고 Play하면 보인다.
3. Adella가 C0a를 직접 하므로 **화면 확인까지의 대기가 없다.** 장대희의 C1·C2는 씬·Runtime을 건드리지 않는다.
4. 임시 아트 생성기 `UiPlaceholderArt.Generate()`(메뉴 `Nova Lux/Generate Placeholder UI Art`)는 UiTheme 슬롯을 조건 없이 덮어쓴다. C0a가 보호 코드를 넣기 전까지 **누르지 않는다.**

## 3. WP별 상세 지시서

  - M3 밖인 단계(하루 끝 1 새벽 방어 결과, 2 새벽 공격·밤 이벤트, 아침 2~4 표적·SNS)는 **순서 자리만** 만들고 "M5" 주석을 단다. 크기 5단계 플래그는 필드만 두고 기본 false(M7). 아침 5(5.1 자격 아침 판정)와 6(자동저장 훅, 실제 저장은 M4)은 만든다.
- **확정(2026-10-29, Adella)**

- 문은 배경에 그려 넣지 말고 **별도 스프라이트**(216×432, 아래 가운데 피벗, `closed`와 `highlight` 두 장)로 만든다. 문 위치나 개수가 바뀌어도 배경을 다시 그리지 않는다.
- 그레이박스로 먼저 그리고 최종으로 간다(3종 비율은 확인함). 이슈 `복도 배경과 문 스프라이트(그레이박스 → 최종)`.

### WP-A4. HUD 아이콘과 타이틀 배경

- 칸 아이콘 4종 `icon_slot_{morning,noon,evening,dawn}.png`(128×128, 흰색). `GameArt.slotIcons`에 순서대로.
- 타이틀 배경 `title_bg.png`(1920×1080). **왼쪽(x≈-560)은 비워 둔다.** 초기화면 버튼이 왼쪽에 세로로 놓인다(`UiTheme.titleMenuX = -560`). `UiTheme.titleBackground`에 넣고, 필드와 `TitleScreen` 표시 코드는 이 WP에서 Adella가 만든다.
- 파일 제작은 지금 가능하다. HUD에 보이는 것은 C3 뒤다. 이슈 `HUD 칸 아이콘과 타이틀 배경`.

### WP-A5. (선택) 여주 스탠딩 러프

- 이름·성격이 미확정이다(기획서 3장, 12장). 4번째 여주는 전여친 갸루이고 옆집 누나는 선배로 바뀌었다. 소꿉친구·선배·후배 3명만 러프로 그린다(id `neighbor`는 선배에 그대로 쓴다). 크기는 가정 600×900. `heroine_<id>_portrait.png`, id는 `childhood`/`neighbor`/`junior`(C1 enum과 같음).
- 우선순위는 가장 낮다. 기획 확정 전에 많이 그리지 않는다.

### 코드가 필요한 아트 작업 → 계약으로 올린 것
